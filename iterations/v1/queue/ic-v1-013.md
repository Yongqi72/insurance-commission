acceptance-criteria:
  - |-
    (源：PRD AC-14 seam review SEAM-F001)
    intent: 用户在批次详情页对某条保单记录人工补录/修改销售人员姓名并保存成功后，无需离开页面或整页刷新，紧邻可见的提成汇总卡片区块立即反映新数据
    oracle: `PolicyRecordTable.vue` 的 `handleSaveSalesName` 成功分支（`ElMessage.success` 之后）emit `sales-name-changed`；`BatchDetailView.vue` 监听该事件，调用 `CommissionSummaryPanel` 实例（模板 ref）的 `refresh()` 方法，触发其重新请求 `GET .../commission-summary`；不触发整页 `loadDetail()` 重新加载（避免不必要的批次详情/明细列表整体闪烁）
    example: Given 批次详情页某条未匹配记录，When 展开该行填写"张三"并保存成功，Then 提成汇总卡片区块在无需刷新页面的情况下更新出现张三的新记录
    golden: false
  - |-
    (源：PRD AC-14/AC-15 seam review SEAM-F001)
    intent: 用户导入 Excel 或删除某次导入后，紧邻可见的提成汇总卡片与保单记录明细表均立即反映记录集合的变化
    oracle: `ImportPanel.vue` 的 `handleStartImport`（导入成功）与 `handleDeleteImport`（删除成功）分支均 emit `records-changed`（此前只有删除分支 emit，导入成功分支本次补齐）；`BatchDetailView.vue` 监听该事件，同时调用 `PolicyRecordTable`（模板 ref）与 `CommissionSummaryPanel`（模板 ref）各自的 `refresh()` 方法
    example: Given 批次详情页已展示 3 条明细，When 导入一份新增 5 条记录的 Excel 成功，Then 保单记录明细表自动增至 8 条、提成汇总卡片同步反映新记录，均无需刷新页面
    golden: false
  - |-
    (技术)
    intent: 联动刷新机制本身不产生额外的可感知副作用（如清空用户正在编辑的表单、重复弹出成功提示）
    oracle: `refresh()` 方法仅重新拉取数据并更新列表/卡片渲染，不重置 `PolicyRecordTable.vue` 内部正在展开编辑的行状态（若用户在明细表里正编辑另一条记录时触发了 `CommissionSummaryPanel.refresh()`，明细表的展开编辑态不受影响）；`refresh()` 内部复用既有 `loadData()`/`loadSummary()` 函数，不重复弹出 `ElMessage.success`（成功提示仍只在原操作的成功分支各出现一次）
    golden: false
