  - |-
    (源：PRD AC-05)
    intent: 用户进入批次详情页能看到该批次下所有保单记录明细，按导入顺序排列，且能用工作单号/保单号/客户名称模糊搜索
    oracle: GET /api/commission-batches/:id/policy-records 按 batchId 过滤，默认按 created_at 升序分页返回 PageResultDto；keyword 存在时对 workOrderNo/policyNo/customerName 三字段做 OR LIKE 模糊匹配；批次不存在返回 1004；结果为空时 data.list 为空数组，前端展示空态
    example: Given 批次内已导入 139 条记录，其中若干工作单号含 "WO2026"，When 传 keyword=WO2026，Then 仅返回工作单号包含该字符串的记录
    golden: false

    oracle: POST /api/commission-batches/:id/policy-records/fill 查询该批次内 sales_fill_source='unmatched' 的记录，按工作单号批量调用地址读自环境变量 SALES_FILL_API_URL 的第三方接口（超时阈值 5s）；地址未配置/超时/调用异常 → 相关记录保持 salesName 为空、sales_fill_source 仍为 unmatched；有返回且命中映射 → salesName=返回值、sales_fill_source='system'；无论命中与否，接口整体返回 200 及 { total, matchedCount, unmatchedCount }，不返回错误码；已是 system/manual 的记录本次不受影响
    example: Given 批次内 50 条记录均为 unmatched 且 SALES_FILL_API_URL 未配置，When 调用回填接口，Then 响应 {total:50, matchedCount:0, unmatchedCount:50}，50 条记录 sales_fill_source 仍为 unmatched
    golden: false

    oracle: PATCH /api/policy-records/:id/sales-name 事务内先读取旧值 → 更新 sales_name=新值、sales_fill_source='manual' → 插入 sales_fill_log(operator=当前登录管理员, changed_at=now, old_value=旧值, new_value=新值) → 返回更新后的保单记录；salesName 为空 → 1001；记录不存在 → 1004；每次修改都新增一条日志，不覆盖/不删除旧日志
