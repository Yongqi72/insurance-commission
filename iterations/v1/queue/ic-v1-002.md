    (源：PRD AC-01)
    intent: 用户填写批次名称提交后，生成新批次并进入详情页，初始状态"进行中"
    oracle: POST /api/commission-batches 请求体 { name }；name 为空或缺失 → 返回错误码 1001；校验通过 → 插入 commission_batch 记录，status 固定初始值 doing，name 不做唯一性校验（允许与已有批次重名）；成功响应 { id, name, status, createdAt }
    example: Given 数据库中已存在名为"2026年8月批次"的批次，When 再次 POST { name: "2026年8月批次" }，Then 创建成功（code=0），生成第二条同名批次，两条记录 id 不同
    golden: false
  - |-

    oracle: GET /api/commission-batches 按 PageQueryDto（page/pageSize）分页，按 created_at 倒序返回 PageResultDto<{ id, name, status, createdAt }>；库中无批次时返回 data.list=[]、data.total=0（非报错，供前端渲染空态）
    example: Given 库中先后创建了 3 个批次 A、B、C，When GET 第一页，Then 返回顺序为 C、B、A
    golden: false
  - |-

    example: Given 批次不存在的 id "999999"，When GET，Then 返回 code=1004
    golden: false
  - |-
    (源：PRD AC-02)
    intent: 用户可在详情页把状态在「进行中/已完成」间手动切换，纯标记不影响任何数据操作
    oracle: 请求体 { status: 'doing' | 'done' }；status 不在该枚举内 → 1001；id 不存在 → 1004；校验通过 → 更新 commission_batch.status 并返回更新后的批次；状态切换本身除更新 status 字段外无其他副作用，不锁定、不校验、不联动导入/回填/补录/导出等其他任何操作的可执行性
    example: Given 某批次当前 status="doing"，When PATCH {status:"done"}，Then 响应 status="done"，其关联的 import_file/policy_record 记录数不变
    golden: false
