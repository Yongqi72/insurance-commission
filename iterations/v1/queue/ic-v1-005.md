acceptance-criteria:
  - |-
    (源：PRD AC-10)
    intent: 管理员可以对阶梯表中任意一档单独执行新增/编辑/删除，每次操作是独立请求、立即提交生效，不需要整表统一保存
    oracle: POST/PATCH 校验 unitPrice 必须为正数（否则 1001）；lowerBound 必须 >=0 且 lowerBound < upperBound（upperBound 为空视为"及以上"，直接通过该项比较，否则 1001）；DELETE 无字段校验；三者各自独立提交、立即生效；删除某档或增改后与相邻档位出现空隙，不阻止本次操作本身
    example: Given 空规则表，When POST {lowerBound:0, upperBound:50, unitPrice:2}，Then 201 新增成功且立即可在 GET /api/commission-tiers 查到该档
    golden: false
  - |-
    (源：PRD AC-11)
    intent: 保存某档时，如果新区间与已有档位重叠，阻止保存并提示冲突档位；如果只是留出空隙（未紧邻），允许保存，但阶梯表在补齐前视为"不完整"，无法用于提成计算
    oracle: 区间为 (下限,上限]；新增/编辑某档时遍历其余档位（PATCH 排除自身 id），若 新lowerBound < 其upperBound(空视为+∞) 且 其lowerBound < 新upperBound(空视为+∞) → 判定重叠 → 拒绝保存返回 1005，错误信息含冲突档位 → 无重叠则允许保存（哪怕留有空隙、起点非 0、或未覆盖到无穷）；完整性判定：全部档位按 lowerBound 排序后，首档 lowerBound===0 且末档 upperBound===null 且相邻档位首尾相接（前一档 upperBound === 后一档 lowerBound），三条同时满足才为 true，任一不满足即为 false；该判定必须实现为导出函数 ruleComplete(tiers)（backend/src/commission-tier/rule-complete.util.ts），GET /api/commission-tiers 与 ic-v1-006 的 commission-summary/commission-report 接口共用同一份实现，不得各自重复实现
    example: Given 已有 (0,50]=2元、(50,100]=2.2元，When 新增 (60,150]=2.4元，Then 保存失败(1005)，提示与 (50,100] 冲突；When 改为新增下限100、上限留空（及以上）、单价2.4元，Then 保存成功，此时 ruleComplete()=true（首档下限0，末档上限留空覆盖到无穷，且相邻档位首尾相接）
    golden: true
  - |-
    (源：PRD AC-12)
    intent: 一目了然看到当前阶梯表，以及表当前是否完整可用
    oracle: GET /api/commission-tiers 按 lowerBound 升序返回 { tiers, ruleComplete }；无任何规则时 tiers=[]、ruleComplete=false；有规则但不完整时前端据 ruleComplete=false 展示"规则不完整（存在空隙），提成计算暂不可用"；完整时不展示该提示
    example: Given 无任何档位，When GET，Then {tiers:[], ruleComplete:false}
    golden: true
  - |-
    (源：PRD AC-13)
    intent: 用户可查看阶梯规则的完整修改历史
    oracle: 每次 POST/PATCH/DELETE 成功后各自插入一条 commission_tier_change_log（operation_type 对应 create/update/delete、operator=当前登录管理员、changed_at=now、before_snapshot/after_snapshot 为 JSON 快照，结构 {lowerBound,upperBound,unitPrice}，create 时 before 为空，delete 时 after 为空）；GET /api/commission-tiers/change-logs 按 changed_at 倒序返回全量列表，API 层把 snapshot 字段解析为对象（非原始 JSON 字符串）；日志只增不改不删，无记录时返回空数组
    example: Given 新增一档后又删除该档，When GET change-logs，Then 返回两条记录，最新的(delete)在前
    golden: false
  - |-
    (技术)
    intent: 非法请求体（unitPrice 非正数/非数字、lowerBound 缺失或非法类型等）必须被参数校验拦截，不能静默通过进入下游冲突判定或落库
    oracle: upsert-commission-tier.dto.ts 对 lowerBound/upperBound/unitPrice 使用完整 class-validator 装饰器（@IsNumber、@Min(0)、@IsOptional 等），全局 ValidationPipe 拦截非法请求并返回 1001
    golden: false
