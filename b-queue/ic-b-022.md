description: |-
  当前状态 → 期望状态：`POST /auth/login`（`auth.controller.ts`）对失败尝试无任何限流或锁定机制，
  `auth.service.ts` 的 `login()` 只做账号名比对 + `bcrypt.compare()` 密码校验，失败即抛
  `UnauthorizedException`，没有任何调用频率限制；系统当前只有单一管理员账号（`ADMIN_USERNAME`/
  `ADMIN_PASSWORD_HASH` 环境变量种子配置，非开放注册），一旦账号名已知（如从部署文档、错误提示或
  社会工程获知），该接口理论上可被无限次密码尝试而不受任何阻拦 → 引入 `@nestjs/throttler`，仅对
  `POST /auth/login` 这一个端点配置时间窗口限流（60 秒内最多 5 次请求，超出返回 429），按客户端 IP
  区分限流键，窗口过后自动重置，不引入按账号的持久化锁定状态（避免唯一管理员被永久锁死且当前系统无
  "忘记密码"自助解锁流程）。

    (源：本轮项目审核会话代码审查新发现，用户已确认转 B 类修复)
    intent: 对 POST /auth/login 短时间内的大量失败尝试，系统能自动限制该来源的进一步请求频率，降低
      密码暴力枚举的可行性；限流窗口过后自动恢复正常访问，不产生永久锁死、不需要人工介入解锁，对合法
      用户的正常登录节奏（偶发一两次输错密码）无感知影响。
    oracle: `auth.module.ts` 引入 `ThrottlerModule.forRoot([{ ttl: 60000, limit: 5 }])`（或等价配置，
      60 秒窗口内最多 5 次）；`auth.controller.ts` 的 `login()` 方法加 `@UseGuards(ThrottlerGuard)`
      （若采用局部而非全局注册，需显式声明），限流键使用 NestJS ThrottlerGuard 默认的按请求方
      IP（`req.ip`）区分。同一 IP 在 60 秒内第 6 次及以后请求（无论账号密码是否正确）返回 HTTP 429，
      响应体走现有 `AllExceptionsFilter` 统一错误信封；60 秒窗口滑动过后同一 IP 恢复可正常请求；不同
      IP 之间互不影响；`auth.service.ts` 的 `login()` 现有账号名比对与 `bcrypt.compare()` 校验逻辑
      不改动。
    example: Given 同一 IP 连续 5 次向 POST /auth/login 发起请求（密码对错不限），Then 前 5 次均正常
      走到 `authService.login()`（返回 200 或 401，取决于密码是否正确）；第 6 次请求 Then 返回 429，
      不再执行密码比对；等待超过 60 秒后再次请求 Then 恢复正常（返回 200 或 401）。
