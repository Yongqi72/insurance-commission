acceptance-criteria:
  - |-
    (用户需求)
    intent: 账单导入文件归档到 OSS 时，按上传当天的年/年月/年月日分层存放，而不是按批次分层
    oracle: 新增共享函数 `buildDatedOssKey(category: 'upload' | 'export', fileName: string, now?: Date): string`，返回 `bill/{category}/{yyyy}/{yyyyMM}/{yyyyMMdd}/{Date.now()}-{fileName}`（`yyyy`/`yyyyMM`/`yyyyMMdd` 均取自调用时刻的本地时间，两位数月/日前补零）；`import.service.ts` 原 `const ossKey = \`imports/${batchId}/${Date.now()}-${fileName}\`` 改为 `buildDatedOssKey('upload', fileName)`；示例：2026-08-28 上传的文件 key 形如 `bill/upload/2026/202608/20260828/{时间戳}-{文件名}`
    example: Given 2026年8月28日上传"7月账单.xlsx"，When 导入接口处理该文件，Then 实际写入 OSS 的 key 为 `bill/upload/2026/202608/20260828/{时间戳}-7月账单.xlsx`
    golden: false
  - |-
    (用户需求)
    intent: 导出的提成报表归档到 OSS 时，同样按导出当天的年/年月/年月日分层存放
    oracle: `commission-report.service.ts` 原 `const ossKey = \`exports/${batchId}/${Date.now()}-${fileName}\`` 改为 `buildDatedOssKey('export', fileName)`；示例：2026-08-28 导出的文件 key 形如 `bill/export/2026/202608/20260828/{时间戳}-{批次名}-提成报表.xlsx`
    example: Given 2026年8月28日导出批次"2026年8月批次"的报表，When 调用导出接口，Then 实际写入 OSS 的 key 为 `bill/export/2026/202608/20260828/{时间戳}-2026年8月批次-提成报表.xlsx`
    golden: false
  - |-
    (技术)
    intent: 日期分层逻辑只写一处，两个调用方复用，不各自拼接
    oracle: `import.service.ts`/`commission-report.service.ts` 均不再包含 `Date.now()`/日期字符串拼接的内联逻辑，统一 import 并调用 `buildDatedOssKey`；`batchId` 不再出现在 key 路径中（旧格式的按批次分层被按日期分层完全取代，非并存）
    golden: false
