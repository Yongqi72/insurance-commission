    (用户需求，2026-08-30 manual-test 验收会话提出)
    intent: 用户在批次详情页"提成汇总"区域及导出的 Excel 报表里，能看到每个投保人分组下有多少
      条记录还未获取到销售人员，而不是这些记录完全消失不可见；提成计算本身不因未匹配记录的存在
      而受阻（此点已是现状，本任务不改变）。
    oracle: `CommissionSummaryGroupDto`/`ExcelBuilderGroup` 新增 `unmatchedCount: number`，值为
      该投保人分组内 `salesFillSource === 'unmatched'` 的记录条数（复用 `getSummary()`/
      `exportReport()` 已有的 `groupByPolicyholder()` 分组结果计算，不重新查库）；`GET
      .../commission-summary` 每个 group 新增 `unmatchedCount` 字段；界面 `CommissionSummaryPanel.vue`
      每张投保人卡片内，`unmatchedCount > 0` 时新增一行"未匹配 {N} 票"（视觉上与已确认销售的行区
      分，如置灰/次要文字色），不论该分组是否还有其他已匹配的销售行，都要展示；`unmatchedCount
      === 0` 时不展示该行；原有 `当前没有已确认销售人员的记录` 空态文案仅在 `items.length === 0
      且 unmatchedCount === 0` 时才保留展示（正常情况下不会出现，因为分组内至少有一条记录，作为
      兜底不删除）；导出 Excel 每个投保人 sheet 的"销售汇总"表在既有销售行之后、合计行之前，
      `unmatchedCount > 0` 时追加一行（销售列写"未匹配"、票数列写 unmatchedCount、提成列写 0 或
      空），既有 `totalRow`（合计行）的票数/金额口径不变，仍只统计已匹配销售的 items（不把未匹配
      折进合计，避免"合计"数字产生误导性变化）；已有字段（ruleComplete/policyholder/items/subtotal
      及 Excel 明细行/合计行）值和类型不变。
    example: Given 某投保人分组下 3 条记录已匹配销售"张三"（3 票）、2 条记录未匹配，When 打开批次
      详情页查看提成汇总，Then 该投保人卡片显示"张三 3 票 · ¥xx.xx"和"未匹配 2 票"两行，合计仍为
      张三那 3 票的金额；When 导出 Excel，Then 该投保人 sheet 的销售汇总表比对应界面多一行"未匹配
      2"，合计行金额/票数与导出前一致（只算张三的 3 票）。

context: |-
  用户在 manual-test 验收会话中提出这条需求时，原话包含"无论保单记录中是否有未匹配的记录都要汇总
  计算"——经排查这句话描述的效果其实已经是现状：`getSummary()` 只有阶梯规则不完整时才整体不计算
  （`ruleComplete: false`），未匹配记录从不阻塞计算，只是被 `buildSummaryItems()` 过滤掉不计入统
  计。真正的缺口是后半句"未匹配到的按投保人单列"：现在分组内的未匹配记录完全不可见，全未匹配的组
  显示通用空态文案、部分未匹配的组里未匹配记录连条数都看不到。评估：纯加法（新增字段+新增展示
  行），不改变现有匹配记录的计算/展示逻辑，判定符合 B 类快速通道条件。已用 AskUserQuestion 确认
  导出 Excel 要同步加未匹配条数，保持界面与导出一致，避免两者口径分叉。
