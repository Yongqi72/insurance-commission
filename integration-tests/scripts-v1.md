# 穿透流脚本索引 · v1

## 后端

脚本：`integration-tests/backend/v1-run-all.sh`（用法见脚本头注释；fixture 生成器：`fixtures/generate-fixtures.js`，导出报表解析器：`fixtures/inspect-xlsx.js`）

隔离说明：flow1/2/3 各自新建独立批次，互不依赖；flow4/flow5 依赖全局唯一一套阶梯规则，必须按 4→5 顺序串行。

| 序号 | 穿透流描述 | 起点 → 终态 | 覆盖 AC |
|---|---|---|---|
| flow1 | 批次创建 → 上传含合法+非法行的 Excel（逐行容错）→ OSS 归档 → 状态标记完成后仍可继续导入 → 附带损坏文件/找不到「账单」sheet 两个文件级失败负例 | 无批次 → 已完成状态的批次，含 3 条成功记录 + 2 条失败记录 + 2 次文件级拒绝 | AC-01/02/03/05 |
| flow2 | 创建批次 → 导入 2 条记录 → 删除该次导入 → 关联记录被硬删除，OSS 原文件不受影响 | 有导入记录的批次 → 该次导入及其记录被撤销 | AC-04 |
| flow3 | 创建批次 → 导入 3 条记录 → 触发开始回填（第三方未配置，全部落回未匹配）→ 人工补录 → 覆盖修改（生成第二条日志，不覆盖旧日志）→ 回填状态筛选 | 全部未匹配的记录 → 1 条人工补录（2 条日志）+ 2 条仍未匹配 | AC-06/07/08/09 |
| flow4 | 新增档位 → 新增重叠档位被拒绝（1005）→ 表不完整 → 补齐档位 → 表完整 → 查看变更历史（被拒绝的操作不产生日志） | 无阶梯规则 → 完整覆盖 0~∞ 的两档规则 | AC-10/11/12/13 |
| flow5（依赖 flow4） | 创建批次 → 导入 3 条记录 → 人工补录常熟组 2 条为同一销售 → 查询提成汇总（验证按局部票数计算 + 未匹配不计入）→ 导出 Excel（按投保人分 sheet）→ OSS 归档 → 导出历史 → 重新下载（不重算） | 规则完整 + 有已补录记录的批次 → 一份已归档的导出报表 + 可重新下载 | AC-14/15/16/17 |

## 前端

脚本：`integration-tests/frontend/v1-run-all.js`（用法：`node v1-run-all.js`；依赖 `integration-tests/frontend/package.json` 的 `playwright`，浏览器二进制经 `npx playwright install chromium` 装好）

**技术选型说明**：CLAUDE.md 列出的 `/pinchtab` 个人工具在本次联调会话的可调用技能清单中实际不可用（未注册），环境亦无其他浏览器自动化能力；已用 Playwright + Chromium 补齐（沙箱环境需在 `chromium.launch()` 显式传 `proxy: { server: <系统代理>, bypass: 'localhost,127.0.0.1' }`，否则本地页面与外部站点均无法访问——`proxy: 'direct://'` 在此沙箱下会整体断网，只有"代理+localhost bypass"这一种组合能同时保证本地/外部可达）。

覆盖场景（11 组主线 + 1 组视觉冒烟，共 30 项断言）：登录 → 批次列表新建批次跳转详情 → 状态切换不锁定 → 导入 Excel 含容错 → 明细搜索 → 回填状态筛选 → **人工补录销售人员 + 提成汇总卡片无需刷新页面即联动更新（ic-v1-013 回归验证）** → 查看补录修改历史 → 导出 Excel + 查看导出历史 → 提成阶梯规则新增/区间冲突字段级提示/未保存离开确认 → 规则变更历史；视觉冒烟：主色覆盖 `--el-color-primary`、视口无横向外溢、顶栏高度 56px（design.md §〇）。
